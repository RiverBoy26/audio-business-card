# Голосовое заполнение визитки

Служебная запись заполняет поля; она не является итоговым рассказом и не публикуется.
ФИО берётся из профиля. Обработка не сохраняет распознанные данные в БД: пользователь
подтверждает результат, после чего фронтенд записывает значения в редактируемые поля.

При настроенной модели защищённый endpoint `POST /api/voice-profile` принимает multipart-поле
`file` и возвращает описанный ниже `VoiceProfile`. Временный аудиофайл удаляется после обработки.
Консольный режим остаётся независимым и запускается теми же командами.

## Как говорить

Говорите обычными законченными фразами, не зачитывая названия полей. В рассказе должны быть
четыре понятные части: одна текущая специальность, технологии, опыт и желаемая должность.

Хороший пример: «Я бэкенд-разработчик. В работе использую Java, Spring Boot, PostgreSQL,
Docker и Git. Опыт работы — два года и шесть месяцев. Хочу работать Middle
Java-разработчиком».

Делайте короткую паузу между частями и произносите технологии по одной. Не говорите только
«моя специальность» или «мой стек» без значения. Для полутора лет лучше сказать «полтора
года», хотя запись «1,5 года» валидатор тоже понимает. Английские названия можно произносить
по-русски: «Джава», «Спринг Бут», «Постгрес», «Докер».

Формальные маркеры не обязательны. Поддерживаются естественные обороты «я …-разработчик»,
«работаю с», «использую», «опыт работы», «ищу работу», «хочу работать/стать». Если назвать
две специальности, поле останется пустым до ручного исправления. Результат всегда нужно
показать пользователю для подтверждения.

## Запуск для разработчика

Нужны JDK 21, Maven и локальная русская модель GigaAM v2 RNNT int8 для sherpa-onnx.
Для WAV от встроенной записи FFmpeg не нужен; для WebM/Opus, MP3 и других контейнеров
FFmpeg должен быть в PATH (либо передайте `--ffmpeg /path/to/ffmpeg`). Модель хранится
локально в `models/gigaam-v2` и исключена из Git. Maven автоматически подключает native
библиотеку sherpa-onnx для Windows x64 или Linux x64.

Из корня репозитория:

```sh
mvn -pl sound-service -am test
mvn -pl sound-service package dependency:copy-dependencies -DskipTests
```

Консольный режим не запускает Spring, HTTP и PostgreSQL:

```sh
# Linux/macOS (на Windows заменить разделитель classpath ':' на ';')
java -cp 'sound-service/target/classes:sound-service/target/dependency/*' \
  audio.business.sound.voice.VoiceProfileCli \
  --text 'Моя специальность бэкенд. Стек джава, постгрес, докер. Стаж один-два года. Ищу Junior Java-разработчик.'

java -cp 'sound-service/target/classes:sound-service/target/dependency/*' \
  audio.business.sound.voice.VoiceProfileCli \
  --audio /path/to/recording.webm --model /path/to/models/gigaam-v2

# Запись с системного микрофона, максимум 30 секунд; Enter завершает запись раньше
java -cp 'sound-service/target/classes:sound-service/target/dependency/*' \
  audio.business.sound.voice.VoiceProfileCli \
  --record 30 --model /path/to/models/gigaam-v2
```

JSON выводится в stdout, сообщения записи и ошибки — в stderr; код ошибки 1.
Не сохраняйте JSON-вывод и записи с персональными данными в репозиторий.
FFmpeg декодирует WebM/Opus, WAV, MP3 и другие поддерживаемые форматы в mono float PCM 16 kHz.
Лимиты: файл до 25 MiB, запись до 120 секунд, декодирование до 30 секунд.
Значение `--record` задаёт максимальную длительность; после окончания речи нажмите Enter.
Временные записи/PCM удаляются. При запуске CLI модель загружается один раз перед
распознаванием. В Spring-приложении `SherpaOnnxTranscriber` создаётся singleton-компонентом
и переиспользуется между запросами, если задано свойство `voice.model-directory`.
Микрофон требует доступного устройства Java Sound; на сервере используйте готовый файл.
При декодировании через FFmpeg удаляется тишина, а типичные хвостовые галлюцинации ASR
вроде «С вами был…», подписей музыки и субтитров исключаются из результата с замечанием.

Пример настройки сервиса без запуска консольного режима:

```yaml
voice:
  model-directory: models/gigaam-v2
  ffmpeg: ffmpeg
  max-seconds: 120
```

## Формат результата

```json
{
  "transcript": "Моя специальность бэкенд. Стек джава, постгрес, докер. Стаж один-два года. Ищу Junior Java-разработчик.",
  "sphere": "Веб-разработка",
  "specialization": "Бэкенд-разработчик",
  "skills": ["Java", "PostgreSQL", "Docker"],
  "experience": {"minMonths": 12, "maxMonths": 24, "raw": "один-два года."},
  "desiredPosition": "Junior Java-разработчик",
  "unknownSkills": [],
  "issues": [],
  "requiresConfirmation": true
}
```

`sphere` — широкая сфера, `specialization` — конкретная специальность.
`experience`: точный стаж имеет одинаковые границы; без опыта — 0/0;
неизвестное/невалидное значение — `null`. Поддерживаются числа, слова до двенадцати,
«полгода», «полтора года», десятичные годы, годы + месяцы, диапазоны. Неточное «около двух лет» требует проверки.
Желаемая должность сохраняется текстом, включая Junior/Middle и т. п.
При отсутствии поля оно `null`, список может быть пустым; проблемы перечисляются в `issues`.
Результат всегда требует подтверждения пользователя, даже при отсутствии замечаний.

## Валидатор и его расширение

1. Разделы выделяются по разговорным смысловым маркерам; специализация также распознаётся
   в коротком вступлении до первого маркера. Должность не влияет на специальность и стек.
2. Канонические названия и явные голосовые алиасы берутся из `resources/voice/*.tsv`.
   20 специальностей в 8 сферах и базовый справочник технологий. Таблицы можно затем
   заменить загрузкой из БД, сохранив структуру результата.
3. Границы слов защищают Java/JavaScript, Git/GitHub, C/C#/C++ от смешивания.
4. Неизвестные названия сохраняются в `unknownSkills`. Опечатка расстояния 1 для слов
   от 5 символов даёт `SKILL_SUGGESTION`, но не заменяет значение автоматически.
5. Разрешена ровно одна специальность. Несколько специальностей, повторённые разделы и
   неверный стаж дают замечания. Явно отрицаемая технология исключается, но весь результат
   с отрицанием всё равно требует ручной проверки.

Основной вариант сейчас — словарь алиасов + смысловые маркеры + проверки. Фонетические и нечёткие
совпадения лучше расширять по реальным ошибкам распознавания, сохраняя подтверждение. LLM-парсер
можно рассмотреть отдельно для свободного рассказа; в текущем варианте его нет.
Не вводите вероятность распознавания на основе расстояния строк: это не confidence Whisper.

## Дальнейшее подключение

`SpeechTranscriber.transcribe(Path)` возвращает текст.
`ProfileValidator.validate(String)` возвращает `VoiceProfile`.
`VoiceProfileService.extract(Path)` связывает оба шага; он не зависит от консоли.
Будущий контроллер принимает multipart-файл, передаёт безопасный временный `Path` сервису
и возвращает `VoiceProfile` как JSON. После редактирования/подтверждения фронт отправляет
данные в сервис визиток. Не сохраняйте распознанные поля автоматически.
Владение загруженным файлом и его удаление обеспечивает вызывающий код.
Веб-запросы к локальной модели нужно ограничить очередью/числом задач, размером и длительностью.
Один recognizer переиспользуется и синхронизирует декодирование; для параллельной обработки
потребуется ограниченный пул отдельных recognizer-экземпляров.
